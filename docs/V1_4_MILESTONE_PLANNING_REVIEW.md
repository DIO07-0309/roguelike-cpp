## 二、四个候选方向的审计结论

### P1-A · SimAI Strategy Audit —— **当前不能作为调优基线** ⚠

**已有** (可运行, ~3 局/秒, 同种子字节级可复现): win_rate/楼层分布/F1 死亡率/Boss 击杀率/per-build/per-relic 统计, 900s 确定性超时。

**致命缺口** (调平衡前必须补, 否则任何 win_rate 变化都和 AI 病理死亡混在一起):
| 缺口 | 现状 |
|---|---|
| 死因分类 | ❌ 无 — 只有楼层直方图, [DMG] 日志有源信息但零聚合 |
| 卡墙/震荡率 | ❌ [PLAYER-FIX] 传送只在日志, 每百局约 29 次却无计数器 |
| 搜刮行为 | ❌ 金币/拾取/特殊房触发数完全未记录 |
| 战斗参与率 | ❌ turns=总帧数, 无战斗帧占比 |
| per-武器 | ❌ RunResult 无武器字段 |
| **per-敌人统计** | ❌ **结构存在但从未填充** — 每份报告 "enemies" 恒为 [] |
| 超时归因 | ❌ 600s 墙钟超时(用 GetTime, **非确定性泄漏点**)与死亡记成同一种结果 |
| 构筑样本 | ❌ 95% 局死于"无构筑" — build 统计样本 1-4 局, 统计学无意义 (AI profile 不随局内成长更新) |

**AI 质量底子**: 会用技能/血低喝药/自动穿装/躲 Boss 前摇; 弱点 = 远程 48px~理想距死区(风筝修过又回滚, 胜率 10%→3.5%)、BT/MCTS 不可用作基线、元素恒火(冰毒内容零覆盖)。

### P2 · Mirror Boss 体验审计 —— **机器深, 戏台浅, 且记忆回路有真 Bug** ⚠⚠

**深度 (真实存在)**: 7 层仲裁(战术链→RL→克隆→Thompson)、风格分类、漂移检测、打断预判、奶量惩罚、镜像时停(用玩家自己的时停 SFX)、双武器槽战术切换、三阶段(观察/镜像/进化)。分析面板确实展示"它读了你的档"。

**两个耐久性 Bug (打脸设计承诺)**:
1. **F15 前任意存档清空镜像记忆** — Boss 未生成时 export 为空 → save_game 用空覆盖 mra/mrb 行 → 上一局学习成果丢失
2. **死亡丢掉本局学习** — F15 战斗中途死亡无存档点, "死给它→它记住你"的承诺实际不成立

**"学会了你"可读性缺口** (全部是"数据已算出但从不演出来"):
- 最爱技能开局 ❌ (`predicted_fav_skill` 只进面板文案)
- 节奏模仿 ❌ (attack_frequency 已算, 镜像攻击 CD 写死 1.2s)
- 闪避方向反制 ❌ (`left_bias` 算完即死代码)
- 历史武器偏好 ❌ (只镜像当前武器, 全程弩流换剑进 F15 就看到剑镜像)
- 战斗中零播报 ❌ (阶段晋升/战术切换/打断成功全部 LOG_INFO 独白)

**最高性价比点**: 把已有的适应时刻播报出来 = 日志换 show_message (近乎零成本); 最爱技能开局 ≈ 10 行; 记忆回路修复 = 存档路径守卫。

### P3 · 美术完成度缺口 —— **标题 A- 到 选关 C+ 的断崖** ⚠

| 屏幕 | 评级 | 一句话 |
|---|---|---|
| 标题(电影海报) | A− | 唯一有构图的屏幕 |
| 游戏 HUD | B+ | 双层血条/技能栏/Boss条 全矢量绘制, 功能最佳 |
| 选档(新) | B | 素卡片 — 火冰毒玩家精灵就在手边却没用 |
| 教程 | B− | 地上物品是色块(主游戏却是精灵) — 自我不一致 |
| Boss 登场 | B− | 无 Boss 立绘(sprite 明明存在) |
| 选关 | **C+** | 黑底+色块+数字, 与标题反差最大 |
| 胜利/死亡/职员 | **C~C+** | 情感高潮时刻是全游戏最简陋的画面 |

**资产缺口 Top**: ① 17/30 敌人共用一张 orc 图(火精灵和石像鬼长得一样) ② 全生物群系一套墙地贴图(仅 tint 差异) ③ 3 个 F5 Boss 共用一图 ④ 16/31 VFX 配方是死数据(元素/Boss/死亡反馈绕开配方系统手写) ⑤ 像素字体已随包(授权齐)却没加载——思源黑体配像素画风格错位 ⑥ 四套图标语言并存 ⑦ 全部精灵静态单帧(贴纸滑动感)。

**统一视觉语言的最大杠杆**: 群系贴图差异化 + 敌人按 enemy_pool 补图, 以及"决策"层面: VFX 收归配方系统 vs 删死数据; 字体选型定案。

## 四、推荐 Roadmap (下一阶段正式排序)

```
M1 (修复批, 小):  Mirror 记忆回路双 Bug + 适应播报 + 最爱技能开局
                   ↳ 理由: 招牌玩法的设计承诺目前是空的, 且成本最低
M2 (插桩批, 小):  SimAI 结果分类/死因/敌人统计/卡墙计数 + 600s 墙钟改帧数
                   ↳ 理由: 先测量后调优; 不动 AI 智能, 只补仪表盘
M3 (视觉便宜三连): 选关/胜利/死亡/选档/登场 用现有精灵+面板升级
                   + 教程物品渲染统一 + VFX 死数据清理决策
M4 (基线采集):    500 局确定性基线 (M2 插桩后才有意义) → 死因/卡墙报告
                   ↳ 第一份可信平衡报告, 决定平衡调优是否立项
M5 (视觉大头):    群系贴图差异 + 敌人按 pool 补图 (按 M4 数据决定敌人优先级!)
                   ↳ 哪个群系死亡最多先补哪个, 用数据驱动美术
M6 (Demo 门禁):   Release Checklist 核对 + README 陌生化重写 + GIF 录制
                   → v1.5.0 Demo Release
```

**排序逻辑**: 修复招牌玩法(承诺兑现) → 给测量工具装仪表(不做智能升级) → 便宜视觉先刷完成度 → 数据基线 → **用数据决定**美术大头和平衡调优 → 最后才发布。

**明确不推荐的**: 现在就做 MCTS/RL 强化(先有仪表盘)、现在就加新内容层(新怪/Boss 第 6 个)、机械继续 G10.10 编号开发。

## 五、待用户拍板的 3 个决策点

1. **M1 Mirror 记忆修复方案**: F15 前存档跳过 mra/mrb 行改写(保留旧值) vs GameScene 缓存 last-known 常量透传 —— 审计倾向后者(语义更清晰)
2. **M3 VFX 双轨制**: 收归配方系统 (17 个死配方接线) vs 删死配置认怂手写 —— 审计倾向"先删后接"(每批接 2-3 个高价值的, 其余删, 避免一次性大改)
3. **字体定案**: 思源黑体 (现代 UI, 已全量加载) vs 随包像素字体 (galmuri/ark-pixel, 授权已备未加载) —— 影响整体视觉语言方向, 建议随 M3 一起做一张对比图给用户选
