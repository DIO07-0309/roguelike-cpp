## 2. Identified Mismatches（按观感权重排序）

| # | 不一致项 | 像素差 | 触发场景 |
|---|---------|--------|---------|
| **M1** | 视觉 32 vs 碰撞 28：四边内嵌 2px | **2px/边**（右/下至 <3px） | 静止贴墙必现 |
| **M2** | 1-tile 走廊（32px 宽）= 视觉盒宽 | 双侧 0~3px **常态嵌入** | 走廊穿行（非边缘情况！） |
| M3 | `width-1` 采样允许穿透 | <1px（右/下） | 停止方向 |
| M4 | 整步回退无贴合 | 停靠间隙 [0,3.33px) 抖动 | 观感不稳定主因 |
| M5 | 重击 1.25x 外扩 | +4px/边 → 嵌入 2→6px | 重击瞬态 |
| M6 | 重击旋转 ±6° 角点摆动 | ±4.2px | 重击瞬态 |
| **M7** | 挥砍前倾朝 facing | 普通 +4 / 重击 +7 → **朝墙攻击峰值嵌入 6/13px** | 攻击瞬态 |
| **M8** | 武器贴图伸出 | 静态 +9.4px；**矛旋转峰刺 +21.4px** | 攻击瞬态 |
| M9 | 阴影椭圆下垂 | +5px 半透明（可忽略） | — |
| M10 | 玩家 vs 怪物贴墙表现割裂 | 2px 系统差 | 同屏对比 |

**已排除**（审计确认无问题）：相机焦点偏差（三重重合✅）、屏震相对嵌入（全世界统一偏移✅）、对角穿缝（28<32 tile 网格角点采样完备✅）、"视觉能走但逻辑停"反向情况（不存在——永远是碰撞先停、视觉入墙）。

**结论：玩家视觉位置 ≠ 真实空间位置。根源是单点设计——视觉盒 32 > 碰撞盒 28，其余全是它的瞬态放大项。**

## 3. A/B/C 最小修复方案

### 方案 A — 碰撞盒放大到 32×32（sync_rect offset 2→0）

- **改 gameplay 碰撞**：✅ 是——受击盒 +12.5%、1-tile 走廊余量 5px→0px（贴缝）、怪物碰撞判定全变
- **影响攻击 SSOT**：❌ 否（rect 中心仍 = position+16）
- **影响 G10.5**：❌ 否（几何不变，仅判定容差变）
- **depth sorting 基础**：❌ 否
- 代价：**平衡回归面最大**（sim 胜率、走廊手感、闪避判定全要重验），收益仅消 2px
- 评估：**不推荐**——为一个 2px 视觉问题冒全局平衡风险

### 方案 B — 绘制基准改碰撞盒（精灵缩至 28×28）

- **改 gameplay 碰撞**：❌ 否（纯绘制侧）
- **影响攻击 SSOT**：❌ 否（中心不变）
- **影响 G10.5**：❌ 否
- **depth sorting 基础**：✅ 是（与怪物/NPC 28 统一，未来 y-sort 有一致尺寸模型）
- 代价：玩家视觉变小 12.5%（32→28），武器锚点 `hw*0.42` 系列联动；16×16 素材 28px 渲染 = 1.75× **非整数缩放**（违反 STYLE_GUIDE 16→32 整数规则，需 28→32 改回又回到老问题）
- 评估：**中等**——统一模型优雅但引入非整数缩放违规

### 方案 C — 保留 32 视觉 + 三个视觉侧微修正（推荐 ⭐）

**C1 朝墙姿态衰减**（消 M7/M8 峰值，~12 行）：
`_attack_pose_rect` / 武器锚点计算时，用现有 `is_walkable` 查 facing 前方 tile——若朝墙，前倾幅度 ×0.3、重击缩放降为 1.1x。瞬态嵌入 13px→3px、矛尖 21px→与剑同档。
纯 draw 侧，零 gameplay 影响。

**C2 停靠贴合**（消 M4 抖动，~8 行）：
移动整步失败时复用 `clamp_displacement` 的二分逻辑（现有 6 次二分，精度 位移/64）贴到墙面——静止停靠从 [0,3.33px) 抖动变为**稳定 0~0.05px**。
这是移动手感修正，对平衡无影响（所有实体通用同一 is_rect_walkable）。

**C3 采样 −1 修正**（消 M3，1 行）：
`game_map.cpp:61` 的 `r.x + width - 1` → `r.x + width`，连续穿透 <1px 归零。**注意**：此改动同样作用于怪物位移判定——影响面极小但属于 gameplay 判定变化，需 sim 回归确认。

- **改 gameplay 碰撞**：C1/C2 ❌；C3 ⚠️ 微（<1px 判定边界）
- **影响攻击 SSOT**：❌ 全部否
- **影响 G10.5**：❌ 全部否
- **depth sorting 基础**：C1 为未来"墙面遮挡 pass"预留了朝墙检测钩子 ✅
- 评估：**推荐**——M1/M2 的 2px 常态嵌入在 C 方案下依然存在，但那是像素艺术的正常容差（怪物 28 也与墙 32 有 4px tile 差）；消除的是全部"动态放大项"（13px/21px 峰值）和抖动

### 组合建议

**C1 + C2 先做**（纯表现层零风险）；**C3 单独 gate**（gameplay 判定，跑 200 局 sim 对比胜率 ±0.5% 内再合入）；A/B 长期搁置——若未来做 depth sorting（墙面上半格后画），M1 的 2px 可被完全掩盖，届时再评估。
